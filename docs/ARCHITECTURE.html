System Architecture

Overview

KRONOS Re is built as a modular, event-driven platform where each domain (asset, liability, risk, etc.) is an independently versioned Python package sharing a common data layer via VaultDB Core.

Data Flow

The canonical data pipeline flows through these stages:

  1. Ingestion — Ceding carrier census data is normalized into the KRONOS canonical schema
  2. Market & Assumptions — Yield curves, mortality tables, and behavioral assumptions are loaded
  3. Projection — Liability cash flows are projected; assets are priced
  4. Scenario — Stochastic and deterministic scenarios stress the balance sheet
  5. ALM & Valuation — Duration gaps, surplus optimization, and mark-to-market are computed
  6. Trading — Hedging strategies are generated and executed programmatically
  7. Risk & Reporting — BSCR capital, GAAP/STAT reserves, and regulatory filings are produced

Technology Stack

  • Language: Python 3.12+ with strict typing
  • Data Layer: DuckLake/DuckDB via vaultdb.data ORM
  • Computation: PyTorch tensors for vectorized pricing, autograd sensitivities
  • API: FastAPI (Core task API + KRONOS router)
  • UI: Python Dash (Dashboard module)
  • AI: Anthropic Claude SDK (KRONOS Assistant chatbot)
  • Compute: Local, Celery, AWS Lambda, AWS Batch (Fargate)

Security Model

All workflow execution is gated by triple verification: approval row existence, validity check, and HMAC-SHA256 token verification. The workflow approval secret is held exclusively by ChatHub and never passed to user processes.
