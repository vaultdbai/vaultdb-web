VaultDB Task Runner Architecture

Problem: Tasks Registered with Wrong Runner

The Issue

When using the FastAPI web interface with runner=local, you may notice that tasks are instances of ServiceTask instead of the base Task class. This happens because:

  1. Task Discovery at Startup: When FastAPI starts, discover_tasks() imports all *_tasks.py files
  2. TED Proxy Resolution: Tasks decorated with @TED.task() resolve to the current runner at import time
  3. Default Runner: The TED proxy uses config.run_type to determine which runner to use (often defaults to "service")
  4. Task Registration: Tasks get registered in the service runner's task registry
  5. Separate Registries: When you request runner=local, it creates a new local runner with an empty task registry

Architecture Overview

┌─────────────────────────────────────────────────────────────┐
│                    TED (Task Execution Dispatcher)          │
│                         Proxy Pattern                        │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ├─> TED.Service  → ServiceRunner → ServiceTask
                       ├─> TED.Local    → LocalRunner   → Task
                       ├─> TED.Batch    → BatchRunner   → BatchTask
                       └─> TED.Function → FunctionRunner→ FunctionTask
                                │
                                │ Each has separate task registry
                                ↓
                    ┌────────────────────────┐
                    │   Task Registry        │
                    │  {                     │
                    │    "task.name": Task   │
                    │  }                     │
                    └────────────────────────┘

Solutions

Solution 1: Use Runner-Specific Decorators (Recommended for Production)

Explicitly specify which runner(s) should have the task:

from vaultdb._state import TED

# Register with specific runner
@TED.Service.task(bind=True)
def my_service_task(self, arg):
    return f"Running on service: {arg}"

@TED.Local.task(bind=True)
def my_local_task(self, arg):
    return f"Running locally: {arg}"

# Register with multiple runners
@TED.Service.task(bind=True, name="shared_task")
def service_version(self, arg):
    return f"Service: {arg}"

@TED.Local.task(bind=True, name="shared_task")
def local_version(self, arg):
    return f"Local: {arg}"

Solution 2: Cross-Register Tasks (Current Workaround)

Modify the _get_runner function in web/api.py to share task registries:

def _get_runner(runner_type: str) -> Any:
    """Get runner instance and ensure it has discovered tasks."""
    if runner_type.lower() not in runner_map:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail=f"Invalid runner type: {runner_type}",
        )

    runner = get_runner(runtype=runner_map[runner_type.lower()])

    # If local runner has no tasks, copy from service runner
    if runner_type.lower() == "local" and not runner.tasks:
        service_runner = get_runner(runtype=RunType.SERVICE)
        runner._tasks = service_runner._tasks.copy()

    return runner

Solution 3: Unified Task Registry (Future Enhancement)

Create a global task registry that all runners can access:

# In vaultdb/compute/registry.py
class GlobalTaskRegistry:
    _tasks = {}

    @classmethod
    def register(cls, name, task):
        cls._tasks[name] = task

    @classmethod
    def get_all(cls):
        return cls._tasks.copy()

Current Behavior

When config.run_type = "service" (default in production)

  • @TED.task() → Creates ServiceTask instances
  • Tasks registered in ServiceRunner._tasks
  • Local runner has empty registry

When config.run_type = "local" (development)

  • @TED.task() → Creates base Task instances
  • Tasks registered in LocalRunner._tasks
  • Service runner has empty registry

Recommended Practice

For maximum flexibility, use explicit runner decorators:

# vaultdb/myapp/tasks.py
from vaultdb._state import TED

# This task can run on service runner (Celery)
@TED.Service.task(bind=True, base=Task)
def distributed_task(self, data):
    # Heavy computation that should run on workers
    return process_data(data)

# This task can run locally (for testing/development)
@TED.Local.task(bind=True)
def quick_task(self, value):
    # Simple task for local execution
    return value * 2

Testing Considerations

In tests, you may want to override the runner:

# In tests
from vaultdb._state import _set_current_runner
from vaultdb.compute.core import Runner

# Force local runner for testing
local_runner = Runner()
_set_current_runner(local_runner)

# Now @TED.task() will use local runner

Configuration

Set the default runner via environment variable:

# For local development
export run_type=local

# For production with Celery
export run_type=service

# For AWS Lambda
export run_type=function

# For AWS Batch
export run_type=batch
