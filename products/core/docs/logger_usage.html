AC Logger Package Usage Guide

The AC Logger package provides comprehensive logging functionality with support for both local filesystem and AWS CloudWatch logging, featuring nested log file management and environment-based configuration.

🚀 Quick Start

Basic Usage

import os
from vaultdb.logger import get_logger

# Set up environment
os.environ["LOG_PATH"] = "logs"
os.environ["LOG_LEVEL"] = "INFO"

# Get a logger
logger = get_logger("my_app")

# Start logging
logger.info("Application started")
logger.warning("This is a warning")
logger.error("An error occurred")

Environment Configuration

Set these environment variables to configure the logger:

# Required
export LOG_PATH="/path/to/logs"

# Optional
export LOG_LEVEL="INFO"                    # DEBUG, INFO, WARNING, ERROR, CRITICAL
export LOG_MAX_FILE_SIZE="10485760"       # 10MB in bytes
export LOG_BACKUP_COUNT="5"               # Number of backup files
export ENABLE_CLOUDWATCH="false"          # Enable CloudWatch logging
export CLOUDWATCH_LOG_GROUP="my-app-logs" # CloudWatch log group
export AWS_REGION="us-east-1"             # AWS region

📁 Nested Log Files

One of the key features is the ability to create nested log files with a stack-based approach:

Manual File Management

logger = get_logger("my_app")

logger.info("Main application log")

# Push a new log file for a specific operation
operation_log = logger.push_log_file("data_processing.log", "operations")
logger.info("This goes to data_processing.log")
logger.warning("Processing 1000 records...")

# Go deeper with another nested file
detail_log = logger.push_log_file("detailed_analysis.log", "operations/details")
logger.info("Detailed analysis of each record")

# Pop back to parent file
logger.pop_log_file()  # Back to data_processing.log
logger.info("Analysis completed")

# Pop back to main file
logger.pop_log_file()  # Back to main application log
logger.info("Data processing finished")

Context Manager Approach (Recommended)

logger = get_logger("my_app")

logger.info("Starting main application")

# Temporary nested logging with automatic cleanup
with logger.nested_log_file("user_session.log", "sessions"):
    logger.info("User logged in")
    logger.info("User performed action X")

    # Even deeper nesting
    with logger.nested_log_file("transaction.log", "sessions/transactions"):
        logger.info("Processing payment")
        logger.info("Payment successful")

    logger.info("User session completed")

# Automatically back to main log
logger.info("Application ready for next user")

🔄 Operation Logging

Track operations with automatic start/end logging:

logger = get_logger("my_app")

# Simple operation tracking
with logger.log_operation("database_migration"):
    logger.info("Migrating user table")
    logger.info("Migrating product table") 
    # Automatically logs start and completion

# Handle exceptions gracefully
try:
    with logger.log_operation("risky_operation"):
        logger.info("Attempting risky operation")
        raise ValueError("Something went wrong")
except ValueError:
    logger.error("Operation failed as expected")

☁️ CloudWatch Integration

Setup

  1. Install boto3: pip install boto3
  2. Configure AWS credentials
  3. Set environment variables:
export ENABLE_CLOUDWATCH="true"
export CLOUDWATCH_LOG_GROUP="my-application-logs"
export CLOUDWATCH_LOG_STREAM="production-instance-1"  # Optional
export AWS_REGION="us-east-1"

Usage

from vaultdb.logger.utils import setup_logging_environment
from vaultdb.logger import get_logger

# Setup CloudWatch logging
config = setup_logging_environment(
    enable_cloudwatch=True,
    cloudwatch_log_group="production-app-logs"
)

logger = get_logger("production_app", config)

# Logs go to both file and CloudWatch
logger.info("Application started in production")
logger.error("Critical error occurred")

# Ensure CloudWatch gets the logs
logger.flush()

🛠️ Advanced Configuration

Development Setup

from vaultdb.logger.utils import create_development_logger

# Pre-configured for development
logger = create_development_logger("dev_app")

# Features:
# - DEBUG level logging
# - Console + file output
# - Nested files enabled
# - No CloudWatch

Production Setup

from vaultdb.logger.utils import create_production_logger

# Pre-configured for production
logger = create_production_logger(
    "prod_app", 
    cloudwatch_log_group="production-logs"
)

# Features:
# - INFO level logging
# - File rotation (50MB, 10 backups)
# - CloudWatch integration
# - Optimized for performance

Custom Configuration

from vaultdb.logger.config import LoggerConfig
from vaultdb.logger import get_logger

config = LoggerConfig(
    log_level="DEBUG",
    log_path="/var/log/myapp",
    max_file_size=100 * 1024 * 1024,  # 100MB
    backup_count=20,
    enable_cloudwatch=True,
    cloudwatch_log_group="custom-logs",
    max_nested_depth=5,
    aws_region="eu-west-1"
)

logger = get_logger("custom_app", config)

📊 Monitoring and Debugging

Get Logger Information

# Current configuration
config_info = logger.get_config_info()
print(f"Logger config: {config_info}")

# Stack information
stack_info = logger.get_log_stack_info()
print(f"Current file: {stack_info['current_file']}")
print(f"Stack depth: {stack_info['stack_depth']}")
print(f"All files: {stack_info['stack_files']}")

# Current log file
current_file = logger.get_current_log_file()
print(f"Logging to: {current_file}")

Environment Validation

from vaultdb.logger.utils import validate_log_environment

validation = validate_log_environment()
if not validation["valid"]:
    print("Issues found:")
    for issue in validation["issues"]:
        print(f"  - {issue}")

    print("Recommendations:")
    for rec in validation["recommendations"]:
        print(f"  - {rec}")

Logger Statistics

from vaultdb.logger.utils import get_logger_stats

stats = get_logger_stats()
print(f"Total loggers: {stats['total_loggers']}")
for name, info in stats["loggers"].items():
    print(f"Logger {name}: {info}")

🏗️ File Organization

The logger creates organized file structures:

logs/
├── my_app.log                    # Main application log
├── my_app.log.1                  # Rotated backup
├── operations/
│   ├── data_processing.log       # Operation-specific logs
│   └── details/
│       └── detailed_analysis.log # Nested operation logs
└── sessions/
    ├── user_session.log          # Session logs
    └── transactions/
        └── transaction.log       # Transaction logs

⚠️ Best Practices

1. Use Environment Variables

# Good: Environment-based configuration
logger = get_logger("my_app")  # Uses LOG_PATH, LOG_LEVEL, etc.

# Avoid: Hardcoded paths
config = LoggerConfig(log_path="/hardcoded/path")

2. Use Context Managers

# Good: Automatic cleanup
with logger.nested_log_file("operation.log"):
    # logging happens here

# Avoid: Manual management (easy to forget cleanup)
logger.push_log_file("operation.log")
# ... logging ...
logger.pop_log_file()  # Easy to forget!

3. Structured Logging

# Good: Consistent log messages
logger.info("User authentication successful", extra={
    "user_id": user.id,
    "ip_address": request.remote_addr
})

# Avoid: Unstructured messages
logger.info(f"User {user.id} logged in from {request.remote_addr}")

4. Error Handling

# Good: Use exception() for errors with traceback
try:
    risky_operation()
except Exception as e:
    logger.exception("Operation failed")

# Also good: Use log_operation context
with logger.log_operation("data_import"):
    import_data()  # Automatically logs errors

5. Resource Cleanup

# Always cleanup when done
try:
    logger = get_logger("my_app")
    # ... use logger ...
finally:
    logger.close()  # Important for CloudWatch

🔧 Troubleshooting

Common Issues

  1. "LOG_PATH not set"
  2. Set the LOG_PATH environment variable

  3. Or use setup_logging_environment(log_path="/path/to/logs")

  4. "Permission denied"

  5. Ensure the log directory is writable

  6. Check file permissions

  7. "CloudWatch not working"

  8. Install boto3: pip install boto3
  9. Configure AWS credentials

  10. Check CloudWatch permissions

  11. "Too many nested files"

  12. Check for missing pop_log_file() calls
  13. Use context managers to avoid stack leaks
  14. Adjust max_nested_depth if needed

Debug Mode

Enable debug logging to see what's happening:

export LOG_LEVEL="DEBUG"

This will show detailed information about file operations, CloudWatch uploads, and configuration loading.
