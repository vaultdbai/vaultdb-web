Code Ownership Setup Guide

This guide explains how to configure GitHub to enforce the CODEOWNERS file for pull request approvals.

📋 Overview

The CODEOWNERS file defines who must approve changes to different parts of the codebase. This ensures that: - Critical code changes are reviewed by domain experts - Security-sensitive files require security team approval - Documentation changes are reviewed by technical writers - Infrastructure changes are reviewed by DevOps teams

🔧 GitHub Configuration

1. Enable Branch Protection Rules

To enforce CODEOWNERS, you need to enable branch protection rules:

  1. Go to Settings → Branches in your GitHub repository
  2. Click Add rule for your main branch (usually main or master)
  3. Configure the following settings:

Required Settings:

✅ Require pull request reviews before merging
✅ Require review from CODEOWNERS
✅ Dismiss stale PR approvals when new commits are pushed
✅ Require status checks to pass before merging
✅ Require branches to be up to date before merging
✅ Include administrators (recommended)

Optional but Recommended:

✅ Restrict pushes that create files that match a globbed pattern
✅ Require signed commits
✅ Require linear history

2. Team Setup

Create the following teams in your GitHub organization:

Core Teams:

  • @your-org/maintainer-team - Project maintainers
  • @your-org/project-leads - Project leadership
  • @your-org/admin-team - Repository administrators

Technical Teams:

  • @your-org/core-team - Core application developers
  • @your-org/math-team - Algorithm and calculation experts
  • @your-org/database-team - Database and persistence experts
  • @your-org/backend-team - Backend infrastructure team

Infrastructure Teams:

  • @your-org/devops-team - DevOps and deployment
  • @your-org/security-team - Security specialists
  • @your-org/ci-team - CI/CD pipeline maintainers

Quality Assurance:

  • @your-org/qa-team - Quality assurance engineers
  • @your-org/test-engineers - Test automation specialists

Documentation:

  • @your-org/docs-team - Technical writers
  • @your-org/release-team - Release management

3. Team Permissions

Configure team permissions appropriately:

Team Repository Permission Purpose
admin-team Admin Full repository access
maintainer-team Maintain Manage repository settings
project-leads Write Review and merge PRs
core-team Write Core development
Technical teams Write Domain-specific reviews
qa-team Write Test and quality reviews
docs-team Write Documentation reviews

📁 Folder Ownership Rules

The current CODEOWNERS configuration provides the following protections:

Core Application Code:

  • /src/ac/calculator.py - Math team + Senior engineers
  • /src/ac/__init__.py - Core team + Senior engineers
  • /src/ac/dao/ - Database team + Backend team

Tests and Quality:

  • /tests/ - QA team + Test engineers
  • /tests/ac/test_calculator.py - Math team + QA team

Infrastructure:

  • /Dockerfile - DevOps team + Security team
  • /entrypoint.sh - DevOps team + Security team
  • /.github/workflows/ - DevOps + CI + Security teams

Documentation:

  • /docs/ - Docs team + Project leads
  • *.md files - Docs team + Project leads

Configuration:

  • /pyproject.toml - DevOps team + Release team
  • /requirements.txt - DevOps team + Security team

🚀 Usage Examples

For Code Changes:

# Changes to calculator.py require approval from @math-team
git add src/ac/calculator.py
git commit -m "Fix floating point precision"
git push origin feature/fix-precision
# → PR will require @math-team approval

For Infrastructure Changes:

# Changes to Dockerfile require DevOps approval
git add Dockerfile
git commit -m "Update base image for security"
git push origin feature/update-docker
# → PR will require @devops-team + @security-team approval

For Documentation:

# Documentation changes require docs team
git add docs/new-feature.md
git commit -m "Add new feature documentation"
git push origin feature/docs-update
# → PR will require @docs-team + @project-leads approval

🔍 Troubleshooting

CODEOWNERS Not Working?

  1. Ensure the file is named exactly CODEOWNERS (no extension)
  2. Check that branch protection rules are enabled
  3. Verify team names match your GitHub organization teams
  4. Ensure users are members of the specified teams

Review Requirements Too Strict?

  • Use wildcards for broader patterns: src/**/*.py
  • Create more specific team assignments
  • Use individual usernames instead of teams for smaller projects

Emergency Overrides:

  • Repository administrators can override CODEOWNERS requirements
  • Use the "Include administrators" setting carefully
  • Consider emergency access procedures for critical fixes
