2. New Submodules to Add

2.1 assumptions (NEW — P0)

Actuarial assumptions are the foundation of all liability and ALM calculations. Without a centralized, versioned assumptions library, every module would embed its own tables inconsistently.

Responsibilities: - SOA/NAIC standard mortality tables (CSO 2017, VBT 2015, SOA LLAT) - Lapse rate tables by product type, policy year, and interest rate environment - Dynamic policyholder behavior models (surrender, partial withdrawal, annuitization) - Surrender charge schedules by product - Expense assumption sets (per policy, per $1000 face, percent of premium) - Crediting rate assumptions for Fixed Annuities and FIAs - Reversion-to-the-mean (RTM) interest rate assumptions for AAT - Assumption version control and effective-dating

Key Models:

MortalityTable          — SOA table with qx by age, sex, duration
LapseRateTable          — Lapse rates by product, year, spread-to-crediting-rate
SurrenderChargeSchedule — Charge % by policy year
ExpenseAssumption       — Admin expense, commission, per-policy costs
CredittingRateAssumption— Minimum guaranteed rates, current crediting rates
BehaviorAssumption      — Partial withdrawal, annuitization election rates
AssumptionSet           — Named, versioned bundle of all above

Key Tasks:

load_soa_mortality(table_name)   — Load SOA published tables
create_assumption_set(name, ...) — Bundle assumptions into a named set

2.2 reporting (NEW — P1)

Generates fully auditable regulatory reports and human-review draft memos. Critical for BMA "Explainability Mandate" and NAIC AG 55 compliance.

Responsibilities: - GAAP reporting: ASC 944 (insurance contracts), ASC 820 (fair value) - STAT reporting: NAIC Life Annual Statement schedules - BSCR reporting: Bermuda Solvency Capital Requirement computation and filing - Attribution analysis: Source-of-change reports showing why reserves/capital moved - Hedge effectiveness reports: Per GAAP ASC 815 / IFRS 9 - Solvency dashboard data feeds (for PE partner read-only access) - Draft memo generation (AI drafts the narrative; human actuary signs) - Audit trail: Every model run, input assumption, and output logged immutably

Key Models:

GaapReport              — GAAP financial statement data
StatReport              — NAIC STAT filing data
BscrReport              — BMA BSCR computation
AttributionReport       — Source-of-change analysis
HedgeEffectivenessReport— Hedge designations and effectiveness testing
SolvencySnapshot        — Point-in-time capital ratios for dashboard
DraftMemo               — AI-generated narrative for human review
AuditRecord             — Immutable log of every computation step

2.3 ingestion (NEW — P2)

Normalizes raw census data from ceding U.S. carriers into the VaultDB data model. First step in the KRONOS Re "Data Ingestion" phase where an actuarial analyst peer-reviews sanity check flags.

Responsibilities: - Census file format parsing (CSV, Excel, RI/delimited, fixed-width legacy) - Field mapping templates per carrier - Data quality validation and sanity check flags - Anomaly detection (outliers in age, face amount, crediting rates) - Policy record normalization into VaultDB liability models - Ingestion job tracking and audit trail - Rejection queue for records requiring human review

Key Models:

IngestionJob            — Tracks a census file import run
PolicyRecord            — Raw normalized policy census record
IngestionFlag           — Sanity check warning or error on a record
FieldMappingTemplate    — Per-carrier column mapping configuration
RejectionQueue          — Records requiring human actuarial review

3. Module Implementation Plans

3.1 liability (P0)

The core actuarial engine. Models annuity and life insurance products as cash-flow-generating liabilities, calculates statutory and GAAP reserves, and interfaces with assumptions for all demographic and behavioral inputs.

Products to Model:

Product Key Features Hedging Complexity
Fixed Annuity (FA) Crediting rate, guaranteed min rate, surrender charges Duration matching
Fixed Indexed Annuity (FIA) Option budget, participation rate, cap/floor Delta/Vega
Variable Annuity (VA) Separate account, GMDB/GMIB/GMWB riders Convexity/Rho
Fixed Deferred Annuity (MYGA) Multi-year guaranteed rate, surrender period Duration matching
Life Insurance (Term/WL) Death benefit, CSV, premium payment Mortality risk

Key Models:

AnnuityPolicy           — Master policy record (FA, FIA, MYGA)
VariableAnnuityPolicy   — VA-specific with rider information
LifePolicy              — Term/whole life policy
PolicyCohort            — Grouped policies for model point compression
CashFlowProjection      — Projected liability cash flows by period
Reserve                 — GAAP/STAT reserve by policy and basis
EmbeddedValue           — VIF (Value In Force) calculations

Key Engines:

AnnuityCashFlowEngine   — Projects FA/MYGA liability cash flows
FiaCashFlowEngine       — Projects FIA cash flows including option cost
VaCashFlowEngine        — Projects VA cash flows with rider utilization
ReserveEngine           — GAAP/STAT reserve calculation (PBR, AG 33, AG 38)
AatEngine               — Asset Adequacy Testing (NY7 scenario runs)

Key Tasks:

project_liability_cash_flows(cohort_id, assumption_set, scenarios)
calculate_reserves(policy_ids, basis, valuation_date)
run_aat(block_id, scenario_set, assumption_set)

3.2 scenario (P0)

Generates economic and actuarial scenario sets used across liability projection, ALM analysis, and stress testing. Supports both deterministic regulatory scenarios and stochastic Monte Carlo sets.

Scenario Types:

Type Use Case Count
NY7 (NAIC AAT) Statutory asset adequacy testing 7 deterministic
BSCR Stress Bermuda regulatory capital ~12 prescribed stresses
Stochastic ESG Pricing, embedded value, risk 1,000–10,000 paths
Reverse Stress Board risk appetite User-defined
Historical Back-testing Configurable window

Interest Rate Models: - Hull-White 1F — Mean-reverting short rate; calibrated to SOFR curve + swaptions - CIR — Non-negative rates; suited for stressed scenarios - LMM (LIBOR Market Model) — Full forward curve simulation; for VA/FIA hedging

Key Models:

ScenarioSet             — Named collection of scenarios (e.g., "NY7_2026Q1")
Scenario                — Individual path with rate/equity/spread vectors
InterestRatePath        — Time-series of forward rates across tenors
EquityPath              — Equity index total return paths
CreditSpreadPath        — Credit spread paths by rating
MortalityScenario       — Shocked mortality/longevity for longevity risk

Key Tasks:

generate_ny7_scenarios(valuation_date)          — NAIC NY7 deterministic set
generate_bscr_stresses(valuation_date)          — BMA prescribed stress set
generate_stochastic_scenarios(model, n, seed)   — Monte Carlo ESG paths
calibrate_hull_white(curve_name, vol_surface)   — Calibrate HW to market

3.3 alm (P0)

The strategic ALM engine — the core of the KRONOS Re competitive advantage. Computes duration gaps, cash flow mismatches, and spread analytics across the combined asset + liability portfolio.

Core Capabilities:

Analysis Description
Duration Gap Asset – Liability modified duration mismatch
Key Rate Duration (KRD) Rate sensitivity at each tenor bucket
Cash Flow Matching Period-by-period asset vs. liability cash flows
Spread Analysis Asset yield vs. liability cost-of-funds
Convexity Gap Asset – Liability convexity mismatch
Greeks Aggregation Net delta/vega/gamma across asset+liability
Surplus Analysis Economic and statutory surplus with sensitivities
Rebalancing Triggers Rule-based alerts when gaps exceed thresholds

Key Models:

AlmSnapshot             — Point-in-time ALM state (date, block, portfolio)
DurationGap             — Asset vs. liability duration by bucket
CashFlowMatchReport     — Period-by-period projected cash flow alignment
SpreadAnalysis          — Yield, liability cost, spread by asset class
SurplusAnalysis         — Economic and statutory surplus decomposition
RebalancingAlert        — Triggered when gap exceeds defined limits
AlmPolicy               — Target duration gap, KRD limits, spread targets

Key Tasks:

compute_alm_snapshot(asset_portfolio, liability_block, assumption_set, scenario)
compute_duration_gap(snapshot_id)
compute_krd_profile(snapshot_id)
compute_spread_analysis(snapshot_id)
run_alm_optimization(snapshot_id, alm_policy_id)  — Suggest rebalancing trades

3.4 trading (P1)

Generates and tracks hedging trades per the KRONOS Re approach: AI drafts the hedge strategy and trade recommendations, the human CIO approves execution. Supports product-specific hedging templates.

Hedging Templates by Product (per KRONOS Re plan):

Product Instrument Strategy
Fixed Annuity UST, SOFR Swaps Duration matching, key-rate targeting
FIA Vanilla calls, swaptions, collars Dynamic delta/vega hedging
Variable Annuity Swaptions, equity puts Convexity and rho management
MYGA SOFR Swaps Duration lock with rolling ladders

Key Models:

HedgingStrategy         — Named template with product type and instruments
TradeRecommendation     — AI-generated suggested trade for human approval
TradeOrder              — Approved trade awaiting/pending execution
TradeExecution          — Confirmed executed trade with fills
Position                — Current holding of a hedging instrument
HedgeEffectivenessRecord— GAAP ASC 815 hedge designation and test result
GreeksAggregation       — Net portfolio Greeks across assets + liabilities
RebalancingPlan         — Batch of recommended trades to close ALM gaps

Key Tasks:

generate_hedge_recommendation(alm_snapshot_id, strategy_id)

3.5 valuation (P1)

Orchestrates the complete valuation run — coordinating asset pricing (via asset), liability valuation (via liability), and producing consolidated reporting inputs. Also handles attribution analysis.

Key Capabilities:

Function Description
Asset Portfolio Valuation Calls asset pricing engines for all held instruments
Liability Fair Value GAAP ASC 820 fair value of insurance liabilities
Embedded Value (EV) VIF + required capital for the block
Adjusted Net Asset Value Economic balance sheet for sidecar
Attribution Analysis Source-of-change between two valuation dates
Delta Valuation Fast approximate re-valuation for Greeks

Key Models:

ValuationRun            — Master record for a complete valuation job
AssetValuationResult    — NPV, duration, Greeks per held instrument
LiabilityValuationResult— Reserve, fair value, VIF per policy cohort
ConsolidatedBalanceSheet— Economic asset + liability positions
AttributionReport       — Source-of-change with components

Key Tasks:

run_full_valuation(block_id, portfolio_id, valuation_date, assumption_set)
run_asset_valuation(portfolio_id, curve_name, vol_surface)
run_liability_valuation(block_id, assumption_set, scenario_set)
compute_attribution(prior_run_id, current_run_id)
compute_embedded_value(block_id, assumption_set, scenario_set)

3.6 risk (P1)

Computes regulatory capital (BSCR), economic capital, and risk metrics. Generates the solvency dashboard data for PE partner visibility. The "Explainability Layer" for BMA compliance.

Key Risk Metrics:

Metric Standard Description
BSCR BMA Bermuda Solvency Capital Requirement
ECR BMA Enhanced Capital Requirement (add-ons)
VaR 99% Internal Value at Risk at 1-year, 99th percentile
CVaR 99% Internal Conditional VaR (tail expectation)
Stress Capital BSCR/NAIC Capital under prescribed stress scenarios
Hedge Ratio Internal % of liability risk economically hedged
Liquidity Coverage BMA Cash/liquid assets vs. 30-day stress outflows

Key Models:

RiskRun                 — Master record for a capital/risk computation
BscrResult              — BSCR components by risk module (C1-C8)
EcrResult               — ECR with any add-ons from BMA
VarResult               — VaR/CVaR at specified confidence and horizon
StressTestResult        — Capital impact under each stress scenario
SolvencySnapshot        — Dashboard: BSCR ratio, ECR ratio, trend
RiskAlert               — Triggered when ratio breaches threshold

Key Tasks:

compute_bscr(valuation_run_id, bscr_scenario_set)
compute_ecr(bscr_result_id, add_on_factors)
compute_var(valuation_run_id, confidence, horizon, scenario_count)
run_stress_tests(valuation_run_id, stress_scenario_set)
generate_solvency_snapshot(risk_run_id)     — Dashboard data
generate_bscr_explainability_memo(risk_run_id)  — AI draft for BMA

6. Cross-Cutting Technical Standards

6.1 Module Skeleton Pattern

Every module follows the asset/market pattern:

{module}/
  src/vaultdb_{module}/
    __init__.py         — Public API exports
    models.py           — Data models (vaultdb.data.Model / TimeSeriesModel)
    tasks.py            — Task functions (integrate with vaultdb.compute)
    engines/            — Computation engines (one class per engine type)
    api.py              — FastAPI router (registered in core web server)
  tests/
  docs/
  pyproject.toml
  requirements.txt
  Dockerfile
  CLAUDE.md

6.2 Compute Pattern

All heavy computation uses vaultdb.compute: - Development: RunType.LOCAL - Async batch jobs: RunType.SERVICE (Celery/Redis) - Long stochastic runs: RunType.BATCH (AWS Batch GPU) - Event-triggered: RunType.FUNCTION (Lambda)

6.3 Data Pattern

All persistent data uses vaultdb.data: - Reference data (products, assumptions): Model - Time-varying data (snapshots, results): TimeSeriesModel - DuckLake catalog on S3 (prod) / local DuckDB (dev)

6.4 Human-in-the-Loop API Pattern

For BMA explainability compliance, every material decision has a two-step API:

POST /api/v1/{module}/recommendations     — AI generates draft
POST /api/v1/{module}/recommendations/{id}/approve   — Human approves

Approval records are stored in AuditRecord with the approver identity.

6.5 PYTHONPATH for Development

When running any non-core submodule:

PYTHONPATH="./core/src:./assumptions/src:./market/src:./{module}/src" python ...

11. AADHYA — Local Development Environment

scripts/aadhya/ is the developer control center for running all KRONOS Re services locally.

Files

File Purpose
supervisord.conf Supervisor config — manages Redis, Celery worker/beat, Flower, VaultDB API, KRONOS dashboard
start.sh Shell launcher (./scripts/aadhya/start.sh start\|stop\|status\|logs\|test\|tasks)
run_tasks.py CLI task runner — lists and runs any task from any module
local_tester.py pytest runner across all modules with correct PYTHONPATH
start_worker.py Celery worker bootstrap with all modules registered
start_beat.py Celery beat scheduler bootstrap

Quick start

# Start everything (Redis + Celery + VaultDB API + KRONOS Dashboard)
./scripts/aadhya/start.sh start

# Check status
./scripts/aadhya/start.sh status

# Run dashboard only (no Celery)
./scripts/aadhya/start.sh dashboard

# List all tasks
./scripts/aadhya/start.sh tasks list

# Run full TED pipeline
./scripts/aadhya/start.sh tasks pipeline --block-id TED-FA-2026

# Run all tests
./scripts/aadhya/start.sh test

# Tail dashboard logs
./scripts/aadhya/start.sh logs kronos-dashboard
