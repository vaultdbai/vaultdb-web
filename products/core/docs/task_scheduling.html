Task Scheduling Guide

This guide explains how to define, schedule, and manage tasks in VaultDB.

Overview

VaultDB provides a flexible task scheduling system that allows you to: - Define tasks using Celery decorators - Schedule tasks using the @scheduled decorator - View all scheduled tasks via the FastAPI endpoint - Automatically discover and register tasks from *tasks.py files

Quick Start

1. Define a Task

Create a task in any *tasks.py file:

from vaultdb.celery.tasks import app

@app.task()
def my_task(arg1, arg2, keyword_arg=None):
    """Your task logic here."""
    print(f"Processing: {arg1}, {arg2}, {keyword_arg}")
    return "Task completed"

2. Schedule a Task

Add the @scheduled decorator to make your task run periodically:

from vaultdb.scheduler import scheduled
from vaultdb.celery.tasks import app
from celery.schedules import crontab

@scheduled(
    schedule=crontab(minute="*/15"),  # Run every 15 minutes
    args=(1, 2),                       # Positional arguments
    kwargs={"keyword_arg": "value"}    # Keyword arguments
)
@app.task()
def my_scheduled_task(arg1, arg2, keyword_arg=None):
    """This task runs every 15 minutes."""
    print(f"Scheduled execution: {arg1}, {arg2}, {keyword_arg}")
    return "Scheduled task completed"

Schedule Types

Crontab Schedules

Use crontab for flexible scheduling based on time:

from celery.schedules import crontab

# Every 15 minutes
schedule=crontab(minute="*/15")

# Every hour at minute 30
schedule=crontab(minute=30)

# Every day at 5:30 AM
schedule=crontab(hour=5, minute=30)

# Every Monday at 7:30 AM
schedule=crontab(hour=7, minute=30, day_of_week=1)

# Every first day of the month
schedule=crontab(hour=0, minute=0, day_of_month=1)

# Weekdays only (Monday-Friday) at 9 AM
schedule=crontab(hour=9, minute=0, day_of_week='mon-fri')

Interval Schedules

Use schedule for simple interval-based scheduling:

from vaultdb.scheduler.schedules import schedule

# Run every 60 seconds
schedule=schedule(run_every=60)

# Run every 5 minutes (300 seconds)
schedule=schedule(run_every=300)

You can also use timedelta:

from datetime import timedelta

# Run every 30 minutes
schedule=timedelta(minutes=30)

# Run every hour
schedule=timedelta(hours=1)

# Run every day
schedule=timedelta(days=1)

Complete Example

Here's a complete example showing different types of scheduled tasks:

"""
Example tasks file: vaultdb/analytics/analytics_tasks.py
"""
from vaultdb.celery.tasks import app, Task
from vaultdb.scheduler import scheduled
from celery.schedules import crontab
from datetime import timedelta

@scheduled(
    schedule=crontab(hour=2, minute=0),  # Daily at 2 AM
    kwargs={"full_sync": True}
)
@app.task(bind=True, base=Task)
def daily_analytics_sync(self, full_sync=False):
    """Run daily analytics synchronization."""
    with self.connect():
        # Database operations here
        if full_sync:
            print("Running full analytics sync...")
        else:
            print("Running incremental sync...")
    return "Analytics sync completed"


@scheduled(
    schedule=crontab(minute="*/5"),  # Every 5 minutes
)
@app.task(bind=True, base=Task)
def refresh_cache(self):
    """Refresh application cache every 5 minutes."""
    with self.connect():
        print("Refreshing cache...")
        # Cache refresh logic
    return "Cache refreshed"


@scheduled(
    schedule=timedelta(hours=1),  # Every hour
    args=("hourly_report",)
)
@app.task()
def generate_report(report_type):
    """Generate reports on an hourly basis."""
    print(f"Generating {report_type}...")
    return f"Report {report_type} generated"

Task Discovery

VaultDB automatically discovers tasks from files matching the pattern *tasks.py or tasks.py in your application.

Discovery Process

  1. On application startup, VaultDB scans for *tasks.py files
  2. All tasks decorated with @scheduled are registered in the ScheduledTaskRegistry
  3. The registry is converted to Celery's beat_schedule format
  4. Tasks become available for periodic execution

File Naming Convention

Your task files should follow one of these patterns: - tasks.py - *_tasks.py (e.g., analytics_tasks.py, cleanup_tasks.py)

FastAPI Endpoints

List All Tasks

Get a list of all registered tasks:

GET http://localhost:8000/tasks

Response:

{
  "tasks": [
    {
      "name": "vaultdb.celery.tasks.scheduled_example_task",
      "doc": "Example scheduled task.",
      "module": "vaultdb.celery.tasks",
      "annotations": ["self", "message", "delay"]
    }
  ]
}

List Scheduled Tasks

Get a list of all scheduled tasks with their schedules:

GET http://localhost:8000/schedules

Response:

{
  "schedules": [
    {
      "name": "vaultdb.celery.tasks.scheduled_example_task",
      "task": "vaultdb.celery.tasks.scheduled_example_task",
      "schedule": "<crontab: */15 * * * * (m/h/dM/MY/d)>",
      "args": ["Scheduled message"],
      "kwargs": {"delay": 1}
    }
  ]
}

Submit a Task Manually

Execute a task immediately (bypassing the schedule):

POST http://localhost:8000/tasks/submit
Content-Type: application/json

{
  "task_name": "vaultdb.celery.tasks.scheduled_example_task",
  "args": ["Manual execution"],
  "kwargs": {"delay": 0},
  "runner": "celery"
}

Response:

{
  "task_id": "abc123-def456-...",
  "status": "SUBMITTED",
  "runner": "celery",
  "message": "Task 'vaultdb.celery.tasks.scheduled_example_task' submitted successfully"
}

Check Task Status

GET http://localhost:8000/tasks/{task_id}/status

Advanced Usage

Task Options

You can pass additional options to the scheduler:

@scheduled(
    schedule=crontab(hour=3, minute=0),
    args=(1, 2),
    kwargs={"foo": "bar"},
    expires=3600,  # Task expires after 1 hour
    priority=5     # Task priority
)
@app.task()
def advanced_task(a, b, foo=None):
    pass

Using VaultDB Connection in Tasks

When using the Task base class, you get automatic connection management:

@scheduled(schedule=crontab(minute="*/10"))
@app.task(bind=True, base=Task)
def database_cleanup(self):
    """Clean up old records every 10 minutes."""
    with self.connect():
        # self.connection is available here
        # Automatically closed when exiting the context
        result = self.connection.execute("DELETE FROM logs WHERE age > 30")
    return f"Cleaned up {result.rowcount} records"

Error Handling and Retries

@scheduled(schedule=crontab(hour="*/6"))  # Every 6 hours
@app.task(
    bind=True,
    autoretry_for=(Exception,),
    retry_kwargs={'max_retries': 3, 'countdown': 60}
)
def resilient_task(self):
    """Task with automatic retry on failure."""
    try:
        # Task logic
        pass
    except Exception as e:
        # Log the error
        print(f"Task failed: {e}")
        raise  # Will trigger auto-retry

Registry API

You can programmatically access the registry:

from vaultdb.scheduler import ScheduledTaskRegistry

# Get all scheduled tasks
registry = ScheduledTaskRegistry()
all_tasks = registry.get_all()

for name, task in all_tasks.items():
    print(f"Task: {name}")
    print(f"  Schedule: {task.schedule}")
    print(f"  Args: {task.args}")
    print(f"  Kwargs: {task.kwargs}")

Running the Scheduler

Celery Beat (Local/Development)

Start Celery Beat to execute scheduled tasks:

celery -A vaultdb.celery.celery beat --loglevel=info

Celery Worker

Start a worker to execute tasks:

celery -A vaultdb.celery.celery worker --loglevel=info

Combined (Development)

Run both beat and worker together:

celery -A vaultdb.celery.celery worker --beat --loglevel=info

Best Practices

  1. Keep Tasks Idempotent: Tasks should produce the same result when run multiple times
  2. Use Specific Schedules: Be precise with your cron expressions to avoid unexpected behavior
  3. Handle Failures Gracefully: Always implement proper error handling
  4. Monitor Task Execution: Use the FastAPI endpoints to monitor scheduled tasks
  5. Test Schedules: Verify your cron expressions using online cron calculators
  6. Avoid Long-Running Tasks: Break down long tasks into smaller chunks
  7. Use Appropriate Timeouts: Set time limits for tasks that might hang

Troubleshooting

Task Not Running

  1. Check if the task is registered: GET /schedules
  2. Verify Celery Beat is running
  3. Check Celery worker logs for errors
  4. Ensure Redis/broker is accessible

Task Running Multiple Times

  1. Verify only one Celery Beat instance is running
  2. Check for duplicate task definitions
  3. Review schedule expressions

Task Not Discovered

  1. Ensure file follows naming convention (*tasks.py)
  2. Check for import errors in the task file
  3. Verify the file is in the correct package

Migration from Old System

If you were using the old schedules.py approach, migrate by:

  1. Remove manual beat_schedule dictionary definitions
  2. Add @scheduled decorator to your tasks
  3. The system will automatically register them

Old way:

app.conf.beat_schedule = {
    "my-task": {
        "task": "tasks.my_task",
        "schedule": crontab(minute="*/15"),
        "args": (1, 2),
    },
}

New way:

@scheduled(schedule=crontab(minute="*/15"), args=(1, 2))
@app.task()
def my_task(a, b):
    pass
