VaultDB Architecture Overview

VaultDB is an advanced data orchestration and execution layer designed for high-performance financial and enterprise workloads. It follows a modular, submodule-based architecture where core functionality is separated from domain-specific logic.

Submodule Functionality Summary

Submodule Description Key Dependencies
core Base package for data orchestration, DuckLake abstraction, task execution (TED), and API. DuckDB, Arrow, Celery, FastAPI
infrastructure AWS CloudFormation templates and Docker configurations for cloud deployment. AWS, Docker
market Market data management (quotes, curves, vol surfaces) and instrument definitions. core, QuantLib
asset Pricing engines and valuation models for financial instruments. core, market, QuantLib, PyTorch
liability Liability modeling, cashflow projections, and reserve calculations. core, assumptions
assumptions Actuarial assumptions (mortality, lapse, expense) and versioned assumption sets. core
ingestion Normalization and import pipeline for policy census data. core, pandas
valuation Portfolio valuation orchestration, mark-to-market, and P&L attribution. core, market, asset
risk Risk analytics (VaR, Greeks, stress testing, regulatory capital). core, market, valuation
scenario Economic scenario generation (stochastic paths) for stress testing. core, market
trading Order management, trade execution, and portfolio construction. core, market
alm Asset-Liability Management (duration gap, NII simulation, EVE). core, market, liability, valuation
reporting Financial (GAAP/STAT) and regulatory (BSCR) filings and audit trails. core, valuation, risk
dashboard Plotly Dash analytical front-end for the KRONOS Re platform. dash, FastAPI
vaultdb-web Static marketing and documentation website for vaultdb.ai. Plain HTML/CSS/JS

Data Flow: End-to-End

  1. Data Ingestion: Raw census data is ingested via the ingestion module, normalized, and stored in S3/DuckLake using the core catalog.
  2. Market Data: Market quotes and curves are fetched and updated daily in the market module.
  3. Valuations: The valuation module orchestrates calls to asset (pricing engines) using market data to compute current values for liability and asset portfolios.
  4. Risk & Scenarios: The scenario module generates future economic paths. The risk module uses these paths and valuation logic to compute VaR and stress test results.
  5. Analytics: The alm module combines asset and liability projections to perform gap and income analysis.
  6. Reporting: Final results are captured by the reporting module for regulatory filings and internal memos.
  7. Interaction: Users interact with the platform through the dashboard (analytical UI) or the vaultdb-web (documentation).
  8. Execution: All compute tasks are dispatched by core/TED to scalable Runners (Celery, AWS Batch, or Lambda).
