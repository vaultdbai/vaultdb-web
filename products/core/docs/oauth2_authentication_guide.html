OIDC and GitHub Authentication Guide

Overview

VaultDB supports OpenID Connect (OIDC) and GitHub authentication. This allows users to connect with any OIDC provider (Google, Microsoft, Okta, etc.) and automatically manage AWS credentials when providers return AWS access keys or via Cognito Identity Pools.

Features

  • OIDC Authorization Code Flow: Standard OIDC authentication
  • Identity Bridging: Automatically swap identity tokens for AWS temporary credentials
  • Token Refresh: Automatic token refresh using refresh tokens
  • AWS Credential Management: Automatically creates AWS profiles when authentication returns AWS credentials
  • Flexible Authentication: Supports authorization code, direct tokens, or AWS credentials
  • S3 Integration: Seamless S3 access using authenticated AWS credentials

Quick Start

1. Configure OIDC Provider

Set the following environment variables:

export AUTH_CLIENT_ID="your-client-id"
export AUTH_CLIENT_SECRET="your-client-secret"
export AUTH_AUTHORIZATION_URL="https://oauth.provider.com/authorize"
export AUTH_TOKEN_URL="https://oauth.provider.com/token"
export AUTH_REDIRECT_URI="http://localhost:8080/callback"
export AUTH_SCOPE="openid profile email"
export AUTH_AWS_PROFILE="vaultdb-auth"  # Optional

2. Basic Usage with Authorization Code Flow

from vaultdb.core import Application, AuthType
from vaultdb.auth import Authenticator

# Step 1: Initialize authenticator with config from environment
authenticator = Authenticator()

# Step 2: Get authorization URL for user to visit
auth_url = authenticator.get_authorization_url()
print(f"Visit this URL to authenticate: {auth_url}")

# Step 3: Handle callback and connect
# (Simplification: Authenticator can handle the local browser flow automatically)
Application.connect(
    catalog="my_database",
    role="vaultdb",
    auth=AuthType.OIDC
)

3. GitHub Usage

from vaultdb.core import Application, AuthType

Application.connect(
    catalog="my_database",
    role="vaultdb",
    auth_token="gho_your_github_token",
    auth=AuthType.GITHUB
)

4. Direct AWS Credentials

If your provider returns AWS credentials directly:

Application.connect(
    catalog="my_database",
    role="vaultdb",
    auth=AuthType.OIDC,
    oauth2_aws_access_key_id="AKIAIOSFODNN7EXAMPLE",
    oauth2_aws_secret_access_key="wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
    oauth2_aws_session_token="session-token",  # Optional
)

Detailed Usage

Authenticator Class

The Authenticator class (in vaultdb.auth) provides full control over OIDC authentication:

from vaultdb.auth import Authenticator

authenticator = Authenticator(
    client_id="your-client-id",
    client_secret="your-client-secret",
    authorization_url="https://oauth.provider.com/authorize",
    token_url="https://oauth.provider.com/token",
    redirect_uri="http://localhost:8080/callback",
    scope="openid profile email",
    bucket="your-s3-bucket",
    aws_region="us-east-1",
    user_identity_pool_id="us-east-1:xxxx-xxxx", # For AWS bridging
)

Getting Authorization URL

# Generate URL with random state (recommended)
auth_url = authenticator.get_authorization_url()

# Or with custom state for CSRF protection
auth_url = authenticator.get_authorization_url(state="my-custom-state")

Authenticating

# Method 1: Authorization code exchange
authenticator.authenticate(authorization_code="code-from-provider")

# Method 2: Direct access token (Bridges to AWS if identity pool configured)
authenticator.authenticate(auth_token="access-token")

# Method 3: Direct AWS credentials
authenticator.authenticate(
    aws_access_key_id="AKIA...",
    aws_secret_access_key="...",
    aws_session_token="..."
)

AWS Profile Creation

When authentication returns AWS credentials, the authenticator automatically creates an AWS profile in ~/.aws/credentials:

# The profile can then be used by boto3 and AWS CLI:
import boto3
session = boto3.Session(profile_name="vaultdb-auth")
s3_client = session.client("s3")

S3 File Download

# Download file from S3 using authenticated credentials
authenticator.download_file(
    s3_key="path/to/file.txt",
    local_path="/local/path/to/file.txt"
)

DuckDB Secrets

The authenticator can create DuckDB secrets for S3 access:

import duckdb

connection = duckdb.connect(":memory:")
authenticator.create_secrets(connection)
# Now DuckDB can access S3 using the AWS credentials

Integration Examples

Integration Examples

Web Application Integration

from flask import Flask, redirect, request
from vaultdb.core import Application, AuthType
from vaultdb.auth import Authenticator

app = Flask(__name__)

# Initialize authenticator
authenticator = Authenticator()

@app.route("/login")
def login():
    """Redirect user to OAuth provider."""
    auth_url = authenticator.get_authorization_url()
    return redirect(auth_url)

@app.route("/callback")
def callback():
    """Handle OAuth callback."""
    code = request.args.get("code")

    # Connect to VaultDB with OIDC
    Application.connect(
        catalog="my_database",
        role="vaultdb",
        auth=AuthType.OIDC,
        oauth2_authorization_code=code,
    )

    return "Authentication successful!"

Command-Line Application

import webbrowser
from vaultdb.core import Application, AuthType
from vaultdb.auth import Authenticator

# Initialize authenticator
authenticator = Authenticator()

# This will launch the browser and start a local server to capture the code
Application.connect(
    catalog="my_database",
    role="vaultdb",
    auth=AuthType.OIDC
)

Configuration

Environment Variables

Variable Description Required
AUTH_CLIENT_ID Client ID Yes
AUTH_CLIENT_SECRET Client Secret Yes
AUTH_AUTHORIZATION_URL Authorization endpoint Yes
AUTH_TOKEN_URL Token endpoint Yes
AUTH_REDIRECT_URI Redirect URI Yes
AUTH_SCOPE Scopes (default: "openid profile email") No
AUTH_AWS_PROFILE AWS profile name (default: "vaultdb-auth") No
AWS_DEFAULT_REGION AWS region (default: "us-east-1") No
USER_BUCKET S3 bucket name No
USER_IDENTITY_POOL_ID Cognito Identity Pool for bridging No

OIDC Provider Examples

Google

authenticator = Authenticator(
    client_id="your-google-client-id",
    client_secret="your-google-client-secret",
    authorization_url="https://accounts.google.com/o/oauth2/v2/auth",
    token_url="https://oauth2.googleapis.com/token",
    redirect_uri="http://localhost:8080/callback",

    token_url="https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token",
    redirect_uri="http://localhost:8080/callback",
)

Okta

    client_id="your-okta-client-id",
    authorization_url="https://{yourOktaDomain}/oauth2/default/v1/authorize",
    token_url="https://{yourOktaDomain}/oauth2/default/v1/token",
    redirect_uri="http://localhost:8080/callback",
)

AWS Credentials from OAuth

Some OAuth providers return AWS credentials directly in the token response. The authenticator automatically:

  1. Extracts AWS credentials from the token response
  2. Creates an AWS profile
  3. Stores credentials in settings for boto3 clients
  4. Enables S3 access and job submission to AWS

Token Response Format

The authenticator looks for AWS credentials in these formats:

{
  "access_token": "...",
  "aws_credentials": {
    "access_key_id": "AKIAIOSFODNN7EXAMPLE",
    "secret_access_key": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
    "session_token": "session-token"
  }
}

Or:

{
  "access_token": "...",
  "aws": {
    "AccessKeyId": "AKIAIOSFODNN7EXAMPLE",
    "SecretAccessKey": "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY",
    "SessionToken": "session-token"
  }
}

Troubleshooting

Common Issues

  1. "OAuth token exchange failed"
  2. Verify client_id, client_secret, and redirect_uri match provider configuration
  3. Check that authorization code hasn't expired (usually expires quickly)

  4. Ensure token_url is correct

  5. "No refresh token available"

  6. Some providers require specific scopes to get refresh tokens

  7. Check provider documentation for refresh token requirements

  8. AWS profile not created

  9. Verify AWS credentials were returned by OAuth provider
  10. Check file permissions on ~/.aws/ directory

  11. Ensure ~/.aws/credentials is writable

  12. S3 access fails

  13. Verify AWS credentials are valid
  14. Check IAM permissions for S3 access
  15. Ensure bucket name is correct

Debugging

Enable debug logging:

import logging
logging.basicConfig(level=logging.DEBUG)

Security Considerations

  1. Client Secret: Never commit client secrets to version control. Use environment variables.
  2. Redirect URI: Always use HTTPS in production.
  3. State Parameter: Always use state parameter for CSRF protection.
  4. AWS Credentials: AWS profiles are created with 600 permissions.
