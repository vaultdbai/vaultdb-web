KRONOS REST API Reference

All KRONOS API endpoints are mounted under /api/v1/kronos on the dashboard server (port 8050). Authentication is via OAuth2 bearer token.

API Router Structure

Chatbot Endpoints

Base: /api/v1/kronos/chatbot

All chatbot endpoints proxy through to ChatHub (port 8060) via httpx.AsyncClient.

Method Path Auth Description
POST /message OAuth Send message to user's AI assistant
GET /history OAuth Get conversation history
DELETE /history OAuth Clear conversation
GET /workflows OAuth List user's workflows
GET /workflows/{id} OAuth Get workflow with step details
POST /workflows/{id}/approve OAuth Approve a workflow
POST /workflows/{id}/execute OAuth Execute an approved workflow
GET /skills OAuth List installed skills
POST /skills/install OAuth Install GitHub skill
DELETE /skills/{name} OAuth Uninstall skill
GET /processes OAuth List active UserProcesses (admin)

Message Request/Response

// POST /chatbot/message
{
  "message": "Run the Q1 valuation pipeline",
  "session_id": "optional-session-id"
}

// Response
{
  "reply": "I've proposed a workflow for the Q1 valuation...",
  "proposed_workflows": [
    {"workflow_id": "abc-123", "name": "Q1 Valuation", "status": "PENDING_APPROVAL"}
  ],
  "message_count": 5
}

Approvals Endpoints

Base: /api/v1/kronos/approvals

Method Path Auth Description
POST /approvals OAuth Create an approval (enforces policy)
GET /approvals OAuth List approvals (filter by subject_id, type, approver)
GET /approvals/{id} OAuth Get single approval record
POST /approvals/{id}/revoke OAuth Revoke an approval
GET /approvals/audit OAuth Full audit trail (optional date filter)

Create Approval

// POST /approvals
{
  "subject_id": "workflow-abc-123",
  "subject_type": "WORKFLOW",
  "subject_name": "Q1 Valuation Pipeline",
  "approver_name": "Alice Smith",
  "notes": "Reviewed all steps and assumptions. LGTM.",
  "submitter_id": "user-bob"
}

Policy enforcement is automatic. If violations occur, returns 403:

{
  "passed": false,
  "violations": [
    {
      "rule": "NoSelfApprovalRule",
      "code": "SELF_APPROVAL_FORBIDDEN",
      "message": "You cannot approve a WORKFLOW that you submitted."
    }
  ]
}

Authentication

All endpoints use OAuth2 bearer tokens. The dashboard server handles the OAuth flow:

Endpoint Purpose
GET /login Redirect to OIDC provider
GET /auth/callback Exchange code for tokens
GET /logout Clear session
GET /health Unauthenticated health check

Session state is stored in an httponly cookie (kronos_session, max age 3600s).
