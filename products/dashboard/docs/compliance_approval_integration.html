Approval Integration — Dashboard Controls

This document describes how the KRONOS Dashboard integrates with the core approval engine to enforce human-in-the-loop governance.

Approval Panel Component

The reusable ApprovalPanel component (components/approval_panel.py) is embedded in the workflow viewer and can be added to any page that requires approvals.

flowchart TD
    subgraph "Pre-Approval View"
        NAME["Approver Name Input
(auto-filled from OIDC)"]
        NOTES["Notes Textarea"]
        TIMER["Countdown Timer
(MinReviewTimeRule)"]
        CHECK["Confirmation Checkbox"]
        BTN["Approve / Reject Buttons"]
    end

    subgraph "Post-Approval View"
        BADGE["Approved Badge"]
        INFO["Approver, Timestamp, Token Suffix"]
        REVOKE["Revoke Button"]
    end

    NAME --> CHECK
    NOTES --> CHECK
    TIMER -->|elapsed| CHECK
    CHECK -->|checked| BTN
    BTN -->|POST /approvals| POLICY["PolicyEnforcer"]
    POLICY -->|passed| RECORD["ApprovalRecord Created"]
    POLICY -->|failed| VIOLATIONS["Inline Violation Messages"]
    RECORD --> BADGE

Panel States

No existing approval: - Displays approver name input (pre-filled from OIDC claims) - Notes textarea (required if policy demands) - Hidden countdown timer (shown when MinReviewTimeRule is active) - "I confirm I have reviewed..." checkbox (must be checked to enable Approve) - Approve and Reject buttons - Violations banner (hidden unless policy fails)

Valid approval exists: - Shows "Approved" badge with approver name, timestamp, and token suffix (last 8 chars) - Audit ID for cross-referencing - Revoke button

ID Namespacing

All component IDs are prefixed with a panel_id parameter to avoid conflicts when multiple panels exist on the same page.

Workflow Viewer Page

The dedicated workflow viewer (/workflow?id={workflow_id}) provides:

MinReviewTimeRule Integration

When the page loads: 1. The server records viewer_opened_at in a server-side session store. 2. This timestamp is unforgeable — the client cannot manipulate it. 3. When the user clicks Approve, the policy engine compares viewer_opened_at to request_time. 4. If insufficient time has elapsed, a countdown timer is displayed.

Live Updates

While a workflow is RUNNING or APPROVED, the page polls for updates every few seconds: - DAG node colors update as steps progress (PENDING → RUNNING → DONE/FAILED) - Step inspector shows current results - Status badge updates

DAG Visualization

Workflows are rendered as directed acyclic graphs using dash-cytoscape with dagre layout:

Clicking a node opens the step inspector showing: - Step name, task path, status - Input kwargs (with resolved references) - Output result JSON - Error message (if failed) - Timing (started_at, finished_at)

Chatbot Page Approval Flow

The chatbot page (/chatbot) includes inline workflow approval:

  1. AI proposes a workflow → appears in "Proposed Workflow" card
  2. Card shows status badge, workflow name, description
  3. Cytoscape DAG rendered inline
  4. Step details on node click
  5. "View full details" link to dedicated workflow viewer
  6. Approve, Reject, Execute buttons with confirmation modal

End-to-End Approval Sequence

sequenceDiagram
    participant USER as Actuary
    participant DASH as Dashboard (8050)
    participant HUB as ChatHub (8060)
    participant CORE as VaultDB Core

    Note over USER: Working in chatbot

    USER->>DASH: "Run Q1 valuation"
    DASH->>HUB: POST /chatbot/{user_id}/message
    HUB->>HUB: ChatEngine → Claude SDK → propose_workflow tool
    HUB->>CORE: submit_workflow()
    CORE-->>HUB: WorkflowRun (PENDING_APPROVAL)
    HUB-->>DASH: {reply, proposed_workflows}
    DASH-->>USER: Show DAG + Approve button

    USER->>DASH: Open /workflow?id=abc
    DASH->>DASH: Record viewer_opened_at (server-side)

    USER->>USER: Review steps, assumptions, costs

    USER->>DASH: Click "Approve" + notes
    DASH->>DASH: Build ApprovalContext
    DASH->>HUB: POST /approvals
    HUB->>CORE: PolicyEnforcer.enforce(context)

    alt Violations
        CORE-->>HUB: {passed: false, violations: [...]}
        HUB-->>DASH: 403 + violations
        DASH-->>USER: Show inline errors
    else Passed
        CORE->>CORE: create_approval() → HMAC token
        CORE-->>HUB: ApprovalRecord
        HUB->>CORE: WorkflowRun.status = APPROVED
        HUB-->>DASH: 200 OK
        DASH-->>USER: "Approved" badge
    end

    USER->>DASH: Click "Execute"
    DASH->>HUB: POST /workflows/{id}/execute
    HUB->>CORE: execute_workflow(id)
    CORE->>CORE: Triple-gate verification
    CORE->>CORE: Execute steps in DAG order
    CORE-->>HUB: WorkflowRun (DONE/FAILED)
    HUB-->>DASH: Updated workflow
    DASH-->>USER: Show results
