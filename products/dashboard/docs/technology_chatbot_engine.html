Chatbot Engine — Claude SDK Integration

The KRONOS AI chatbot runs inside each UserProcess as a ChatEngine instance. It uses the Anthropic Claude SDK to power conversational interactions with actuaries and CIOs.

Engine Architecture

flowchart TD
    USER["User Message"] --> ENGINE["ChatEngine"]
    ENGINE --> CLAUDE["Anthropic API
claude-sonnet-4-6"]
    CLAUDE -->|end_turn| REPLY["Text Reply"]
    CLAUDE -->|tool_use| DISPATCH["dispatch_tool()"]
    DISPATCH --> TOOLS["Tool Implementations"]
    TOOLS --> RESULTS["Tool Results"]
    RESULTS --> ENGINE
    ENGINE -->|loop max 20 iterations| CLAUDE

ChatEngine Configuration

ChatEngine(
    user_id="user-alice",
    block_id="TED-FA-2026",
    model="claude-sonnet-4-6",
    max_tokens=8192,
    max_tool_iterations=20,
)

System Prompt

The engine instructs Claude to: - Describe available KRONOS modules (liability, ALM, trading, risk, valuation, etc.) - Use tools to explore data before proposing actions - Propose workflows (not execute directly) — the human approves first - Structure workflow steps with proper dependencies

Conversation Loop

sequenceDiagram
    participant USER as User
    participant ENGINE as ChatEngine
    participant CLAUDE as Claude API
    participant TOOLS as Tool Dispatch

    USER->>ENGINE: send("Run Q1 valuation")
    ENGINE->>ENGINE: Append to history

    ENGINE->>CLAUDE: messages.create(tools=TOOL_DEFINITIONS)
    CLAUDE-->>ENGINE: tool_use: list_modules

    ENGINE->>TOOLS: dispatch_tool("list_modules", {})
    TOOLS-->>ENGINE: {modules: {...}}

    ENGINE->>CLAUDE: messages.create(tool_results)
    CLAUDE-->>ENGINE: tool_use: propose_workflow

    ENGINE->>TOOLS: dispatch_tool("propose_workflow", {name, steps})
    TOOLS-->>ENGINE: {workflow_id, status}

    ENGINE->>CLAUDE: messages.create(tool_results)
    CLAUDE-->>ENGINE: end_turn: "I've proposed a workflow..."

    ENGINE-->>USER: MessageResponse(reply, proposed_workflows)

Available Tools

The AI has access to these tools via TOOL_DEFINITIONS:

Discovery Tools

Tool Input Output Purpose
list_modules — Available KRONOS modules with task counts Discover what the platform can do
get_block_info block_id Portfolio summary Understand the data being worked with

Workflow Tools

Tool Input Output Purpose
propose_workflow name, description, steps[] {workflow_id, status} Submit a multi-step pipeline for approval
list_workflows — Recent workflows Check existing workflow history
get_workflow workflow_id Full workflow with steps Inspect a specific workflow

Workspace Tools

Tool Input Output Purpose
read_workspace_file path File content Read user's files
write_workspace_file path, content Success confirmation Write to user's workspace
list_workspace subdir (optional) File listing Browse workspace contents

Skill Management Tools

Tool Input Output Purpose
install_skill github_repo, git_ref Skill manifest Install a GitHub plugin
list_skills — Installed skills Check what's installed

Tool Dispatch

All tools are dispatched via dispatch_tool(tool_name, tool_input, user_id, block_id):

  • user_id and block_id are automatically injected — the AI never sees them as parameters.
  • Module tasks are resolved via _MODULE_REGISTRY which maps module names to their task modules.
  • Results are returned as JSON strings to the conversation loop.

Workflow Builder

When the AI calls propose_workflow, the workflow_builder module:

  1. Validates the definition:
  2. steps array must exist and be non-empty
  3. Each step requires id, name, task
  4. Step IDs must be unique
  5. depends_on references must exist
  6. No self-dependencies

  7. on_failure must be "abort" or "continue"

  8. Normalizes each step:

  9. Fills defaults: id (step_NNN), timeout (600s), on_failure (abort)

  10. Ensures all required fields are present

  11. Generates a workflow payload with UUID and submits via ChatHub's internal API.

Cytoscape DAG Rendering

The workflow_to_cytoscape() function converts workflow steps into a format compatible with dash-cytoscape:

# Nodes
{"data": {"id": "step_001", "label": "Project Cash Flows", "task": "liability.tasks...", "status": "PENDING"}}

# Edges (from depends_on)
{"data": {"source": "step_001", "target": "step_002"}}

Status colors: - PENDING: slate (#94a3b8) - RUNNING: blue (#3b82f6) - DONE: green (#22c55e) - FAILED: red (#ef4444) - SKIPPED: amber (#f59e0b)

Workspace System

Each user gets an isolated workspace:

{WORKSPACE_ROOT}/{user_id}/
    workflows/     — Saved workflow JSON files
    data/          — User-uploaded or exported data
    reports/       — Generated report HTML
    .venv/         — Isolated Python virtualenv
    .skills/       — Cloned skill repositories

Path traversal protection: All file operations go through safe_path(user_id, *parts) which resolves the path and raises PermissionError if it escapes the user's workspace.

Skill Manager

Users can install GitHub-hosted skills (plugins) that extend the chatbot:

  1. Validation — Only github.com repos accepted. Optional allowlist via SKILL_GITHUB_ALLOWLIST.
  2. Clone — git clone into {workspace}/.skills/{skill_name}/.
  3. Manifest — Parses kronos-skill.toml for name, version, entry_point.
  4. Install — pip install --editable into user's isolated virtualenv.
  5. Register — If the skill declares a visualizer_subject_type, it's registered in the SKILL_REGISTRY for custom rendering.

Skill Manifest

[skill]
name = "bscr-visualizer"
version = "1.0.0"
description = "Custom BSCR risk waterfall visualization"
entry_point = "bscr_viz.tools:get_tool_definitions"
visualizer_subject_type = "REPORT"
visualizer_entry_point = "bscr_viz.layout:build_layout"
label = "BSCR Risk Waterfall"
