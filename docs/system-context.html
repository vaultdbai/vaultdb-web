VaultDB System Context (Root)

Functional Purpose

VaultDB is an AI-native financial orchestration platform for the Bermuda insurance/reinsurance industry, specialized in capturing the "Complexity Tax" through algorithmic efficiency and regulatory precision.

Documentation Architecture Standards

As mandated by the BMA (Bermuda Monetary Authority) and platform policy, all modules must implement a structured documentation hierarchy. This ensures explainability for human fiduciaries and precision for AI agents.

1. Mandatory Folder: <submodule>/docs/

No functional change is allowed without corresponding documentation in the following categories:

  • Executive Summary (index.md): The functional mission statement.
  • Actuarial Methodology (actuarial/):
  • Persona: Chief Actuary, Regulators.
  • Requirement: LaTeX formulas, statutory/GAAP basis, and QuantLib settings.
  • Technical Architecture (technology/):
  • Persona: Developers, DevOps.
  • Requirement: Mermaid diagrams, DuckDB/Parquet schemas, and API signatures.
  • Compliance & Explainability (compliance/):
  • Persona: Internal Audit, Chief Risk Officer.
  • Requirement: AuditRecord logs, HMAC approval policies, and AI explainability traces.

2. Documentation Portal (vaultdb.ai)

The build_docs.py script automatically processes these folders into the public-facing portal hosted under vaultdb-web/.

  • Platform-wide docs -> vaultdb-web/docs/
  • Module-specific docs -> vaultdb-web/products/<name>/docs/

3. AI Agent Guidelines

When generating or refactoring code: 1. Always check the module's system-context.md. 2. Update the corresponding docs/technology/ file with sequence diagrams if a new workflow is added. 3. Update docs/actuarial/ if a mathematical formula or basis is changed. 4. Ensure the docs/compliance/ section reflects any changes to human-in-the-loop approval gates.
