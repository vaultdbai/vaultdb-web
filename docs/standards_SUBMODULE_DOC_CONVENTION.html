Documentation Standards

Submodule Documentation Convention

Every KRONOS submodule follows a consistent documentation structure to ensure discoverability and maintainability.

Required Files

  • CLAUDE.md — AI assistant guidance (points to system-context.md)
  • system-context.md — Architecture, coding standards, and behavioral guardrails
  • README.md — Human-readable module overview

Source Code Structure

  • src/vaultdb_<module>/models.py — DuckLake ORM models
  • src/vaultdb_<module>/tasks.py — High-level task functions
  • src/vaultdb_<module>/engines/ — Computation engines
  • tests/ — Pytest test suite (smoke, model, engine, integration)

Coding Standards

  • Python 3.12+ with strict typing (disallow_untyped_defs = True)
  • Ruff formatter (160 char limit, double quotes)
  • MyPy static analysis
  • All tests via pytest with PYTHONPATH configured by .devcontainer/pythonpath.sh
  • Use vaultdb.logger (never print()), vaultdb.config (never os.getenv())
