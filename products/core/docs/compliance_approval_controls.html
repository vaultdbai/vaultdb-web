Approval Controls & Audit Trail

This document describes the compliance controls built into the VaultDB approval engine, designed to meet BMA (Bermuda Monetary Authority) explainability mandates and NAIC AG 55 requirements.

Control Framework

Principle: AI Proposes, Human Disposes

Every material action in the KRONOS Re platform follows a two-step pattern:

  1. AI drafts — The chatbot proposes a workflow, report, or trade recommendation.
  2. Human approves — A qualified actuary, CIO, or compliance officer reviews and cryptographically signs.

No AI-proposed action can execute without a verified human approval. This is enforced cryptographically, not just procedurally.

Audit Trail Structure

What Is Captured

Every ApprovalRecord captures:

Category Fields Purpose
Subject subject_id, subject_type, subject_name What was approved
Approver Identity approver_id, approver_email, approver_name, approver_roles Who approved (full OIDC claims)
Request Context session_id, ip_address, user_agent Where and how the approval was made
Separation of Duties submitter_id Who created the subject (for self-approval checks)
Timing approved_at When the approval was made (UTC)
Review Evidence notes Approver's written review comments
Cryptographic Proof token, key_version HMAC-SHA256 binding approval to identity
Revocation is_valid, revoked_by, revoked_at, revoked_reason Full revocation audit

What Is NOT Exposed

  • The full HMAC token is never sent to API clients. Only the last 8 characters (token_suffix) are exposed for display purposes.
  • Key material (actual secret bytes) is never stored in the database. Only the integer key_version is persisted.

Each subject type can have its own ApprovalPolicy with different rule configurations.

Policy Rules — Compliance Mapping

Rule Compliance Requirement How It Works
RequiredRolesRule Role-based access control (BMA governance) Only users with specific OIDC roles can approve certain subject types
NoSelfApprovalRule Separation of duties (SOX, BMA) The person who submits a workflow cannot approve it
MinReviewTimeRule Due diligence (BMA explainability) Approver must spend a minimum time reviewing before signing. Timer is server-set and unforgeable.
RequireNotesRule Documentation requirement (audit trail) Approver must provide written review comments
ExpiryRule Approval freshness (regulatory timeliness) Approvals expire after a configurable window
SingleApproverRule Duplicate prevention Same approver cannot sign the same subject twice

Cryptographic Guarantees

What HMAC-SHA256 Proves

  1. Integrity — The approval record has not been tampered with since creation.
  2. Binding — The token is mathematically bound to the specific approval_id, subject_id, approver_id, approver_email, and approved_at timestamp.
  3. Non-forgeability — Without the secret key, no entity (including the AI) can create a valid token.

The WORKFLOW_APPROVAL_SECRET (and versioned keys) are held exclusively by ChatHub. UserProcesses are spawned with a stripped environment that explicitly denies access to approval secrets, AWS keys, and database URLs.

Key Rotation

The versioned key system allows seamless rotation:

  1. Current key version is 3.
  2. Admin adds version 4 to AWS Secrets Manager.
  3. Sets current_version: 4.
  4. New approvals use key v4. Old tokens (v1, v2, v3) remain verifiable.
  5. Retired versions can be removed after their approvals expire.

Revocation

Approvals can be revoked at any time:

revoke_approval(subject_id, revoked_by="admin@kronos.re", reason="Updated assumptions require re-approval")

Revocation is recorded immutably: - is_valid is set to False - revoked_by, revoked_at, revoked_reason are captured - The original approval record is preserved (never deleted) - Any pending execution will fail at the triple-gate check

Querying the Audit Trail

# All approvals for a workflow
get_audit_trail(subject_id="wf-001", subject_type="WORKFLOW")

# All approvals by a specific person
get_audit_trail(approver_id="user-alice")

# All approvals since a date
get_audit_trail(since=datetime(2026, 1, 1, tzinfo=UTC))

# Full audit trail (all records)
get_audit_trail()

Dashboard Integration

The approval panel component (dashboard/components/approval_panel.py) provides:

  • Pre-approval view: Approver name input, notes textarea, countdown timer (for MinReviewTimeRule), confirmation checkbox, Approve/Reject buttons
  • Post-approval view: Approver name, timestamp, token suffix, audit ID, Revoke button
  • Violation display: Inline error messages when policy rules fail
