This file contains the absolute source of truth for the vaultdb.asset package. Before suggesting any code, verify it aligns with the standards below.

System Context: VaultDB Asset

Package Mission vaultdb.asset provides pricing engines, valuation models, and analytics for financial instruments. It consumes market data and market objects from vaultdb.market and applies QuantLib pricing engines (Black-Scholes, Hull-White, Heston, Vasicek, G2++, etc.) to compute instrument valuations, risk sensitivities, and cashflow projections.

Dependencies: vaultdb.core (data layer, settings), vaultdb.market (market data, curves, instruments).

Tech Stack

  • Language: Python 3.12+ (Strict typing: disallow_untyped_defs = True)
  • Data Layer: DuckLake/DuckDB via vaultdb.data.Model and vaultdb.data.TimeSeriesModel
  • Core Dependency: vaultdb.core>=3.18.0
  • Market Dependency: vaultdb.market>=0.1.0 — for quotes, curves, vol surfaces, instruments
  • QuantLib: QuantLib>=1.33 — reference pricing engines, curve bootstrapping
  • PyTorch: torch>=2.0.0 — vectorized bulk pricing, torch.autograd for Greeks, GPU support
  • Tooling: Ruff (160 char limit), MyPy, Pytest

Project Map

  • /src/vaultdb_asset/: Base package.
    • device.py — CPU/GPU device management
    • market_environment.py — QuantLib → PyTorch tensor bridge
    • results.py — ValuationResult TimeSeriesModel
    • cashflows.py — Shared cashflow schedule → padded tensor matrices
    • tasks.py — Portfolio/instrument pricing orchestration
    • engines/ — All pricing engines (bond, swap, option, capfloor, swaption, fx_forward, cds, fra)
    • engines/base.py — PricingEngine ABC + TorchMixin (autograd, normal CDF/PDF)
  • /tests/: Unit and integration tests.
  • /docs/: Architecture documentation and module guides.

Key Design Decisions

Valuation Date

ALWAYS use vaultdb.settings.valuation_date as the QuantLib evaluation date. Never accept ad-hoc dates.

Market Data Consumption

Fetch curves, quotes, and surfaces from vaultdb.market models. Never duplicate market data definitions here.

Core Skills Reference

Read core/skills/ markdown files (e.g., data-modeling.md, crud.md, settings.md) before writing code.

Behavioral Guardrails (No-Go Zones)

  • Strict Configuration: NEVER use os.getenv or os.environ directly. Use vaultdb.config.
  • No Prints: NEVER use print(). Use vaultdb.logger.
  • No Peewee: NEVER import from peewee. Use vaultdb.data column types.
  • Market Data Here: DO NOT define quote models, curves, or instruments in this repo — those belong in vaultdb.market.
  • Pristine Workspace: Clean up temporary files immediately.
  • Documentation: ALWAYS update /docs/asset_overview.md when adding, modifying, or removing modules, engines, public API, or architectural decisions. Keep documentation in sync with the code at all times. After any structural change, verify that the docs reflect the current state.

Coding Standards

  • Ruff: Exclusive linter/formatter. 160 char line limit. Double quotes.
  • Imports: Single-line, from __future__ import annotations in every file.
  • Typing: Mandatory everywhere. mypy src/ must pass.
  • Testing: pytest + unittest.mock. >90% coverage. Mock external services.

PYTHONPATH

Devcontainer: set automatically — just run pytest tests/.

Standalone (replace $REPO_ROOT with the parent directory containing all submodules):

export PYTHONPATH="$REPO_ROOT/core/src:$REPO_ROOT/market/src:$REPO_ROOT/asset/src"
