VaultDB Authentication Guide

VaultDB supports a unified, provider-agnostic authentication system based on OpenID Connect (OIDC) and GitHub.

1. Global Configuration

You can configure any OIDC-compliant provider using the following environment variables:

Variable Description Example
AUTH_TYPE Type of authentication oidc, github, basic, iam_role
AUTH_CLIENT_ID Client ID your-app-id
AUTH_CLIENT_SECRET Client Secret your-secret
AUTH_AUTHORIZATION_URL Browser login endpoint https://login.microsoftonline.com/.../authorize
AUTH_TOKEN_URL Token exchange endpoint https://login.microsoftonline.com/.../token
AUTH_REDIRECT_URI Your callback URL http://localhost:8080/callback
AUTH_SCOPE Requested OIDC scopes openid profile email

2. Provider Specific Templates

A. AWS Cognito (OIDC Mode)

Use the values provided by the infrastructure/cloudformation/cognito-auth.yaml stack outputs.

export AUTH_TYPE="oidc"
export AUTH_CLIENT_ID="<UserPoolClientId>"
export AUTH_AUTHORIZATION_URL="https://<domain>.auth.<region>.amazoncognito.com/oauth2/authorize"
export AUTH_TOKEN_URL="https://<domain>.auth.<region>.amazoncognito.com/oauth2/token"
export AUTH_REDIRECT_URI="http://localhost:3000/callback"

B. Microsoft Entra ID (Azure AD)

Register a "Web" application in Azure Portal and set the redirect URI.

export AUTH_TYPE="oidc"
export AUTH_CLIENT_ID="00000000-0000-0000-0000-000000000000"
export AUTH_CLIENT_SECRET="your-client-secret"
export AUTH_AUTHORIZATION_URL="https://login.microsoftonline.com/<tenant>/oauth2/v2.0/authorize"
export AUTH_TOKEN_URL="https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token"
export AUTH_REDIRECT_URI="http://localhost:8080/callback"

C. GitHub

export AUTH_TYPE="github"
# For browser flow:
export AUTH_CLIENT_ID="your-github-client-id"
export AUTH_CLIENT_SECRET="your-github-client-secret"
export AUTH_TOKEN_URL="https://github.com/login/oauth/access_token"
# Or use a Personal Access Token directly:
# Application.connect(auth_type=AuthType.GITHUB, auth_token="gho_...")

D. Auth0 / Okta

export AUTH_TYPE="oidc"
export AUTH_CLIENT_ID="your-client-id"
export AUTH_AUTHORIZATION_URL="https://your-tenant.auth0.com/authorize"
export AUTH_TOKEN_URL="https://your-tenant.auth0.com/oauth/token"

3. Role-Based Access Control (RBAC)

Instead of giving everyone the same permissions, you can group users into different roles (e.g., Admin vs User) based on their identity provider groups.

How it works:

  1. Identity Provider: Configure your provider (Microsoft, Okta, etc.) to include a "groups" or "roles" claim in the ID token.
  2. AWS Identity Pool: The infrastructure/cloudformation/cognito-auth.yaml template defines Rules-based mapping.
  3. Dynamic Permissions: When a user logs in, AWS inspects the claim and automatically assigns them the corresponding IAM Role (VaultDBAdminRole or VaultDBUserRole).

Mapping Examples:

Provider Claim Key Value Example Resulting AWS Role
Microsoft Entra roles VaultDB.Admin VaultDBAdminRole (Full Admin / vaultdb)
Okta groups DataAdmins VaultDBAdminRole (Full Admin / vaultdb)
Any (Default) Any valid login VaultDBStandardRole (Restricted)

4. Developer API: Checking Roles

You can programmatically check the user's role in your application:

from vaultdb.auth import get_authorized_role
from vaultdb.core import settings

# After Application.connect()
print(f"Current User Role: {settings.role}")

5. Verification & Security

  • JWKS Fetching: VaultDB dynamically fetches public keys from the provider's iss URL (OpenID Discovery).
  • Caching: Fetched keys are cached in the commitlog_directory to ensure performance and offline verification stability.
  • Audience Check: The system validates that the token was issued for your configured AUTH_CLIENT_ID.

6. Development Utility

For local development or CLI usage with a browser:

from vaultdb.core import Application, AuthType

Application.connect(
    auth=AuthType.OIDC,
    # System will automatically use AUTH_* environment variables
)

This will launch your system browser, allow you to login via your chosen provider, and automatically receive the token.
