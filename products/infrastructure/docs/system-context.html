System Context: VaultDB Infrastructure

Package Mission infrastructure manages the AWS Cloud-native deployment of the VaultDB platform. It provides CloudFormation templates for VPC networking, IAM roles, ECS clusters, AWS Batch environments, Lambda functions, Cognito authentication (OAuth 2.0), S3 storage, and Redis caching. It also contains Dockerfiles for various execution environments (Lambda, Batch CPU/GPU, Service).

Dependencies: AWS CLI, Docker, CloudFormation.

Tech Stack

  • Infrastructure as Code: AWS CloudFormation (YAML)
  • Containerization: Docker
  • Cloud Platform: AWS (ECS Fargate, AWS Batch, Lambda, S3, Cognito, ElastiCache Redis, Secrets Manager)
  • Authentication: OAuth 2.0 (via Cognito)

Project Map

  • cloudformation/: Modular CloudFormation templates.
    • master-stack.yaml: Main orchestration.
    • vpc-networking.yaml: VPC/Networking.
    • iam-roles.yaml: Centralized IAM.
    • cognito-auth.yaml: OAuth 2.0 / Cognito.
    • ecs-service.yaml: ECS Fargate setup.
    • batch-environments.yaml: Batch CPU/GPU setup.
  • docker/: Environment-specific Dockerfiles.
    • Dockerfile.lambda, Dockerfile.batch-cpu, Dockerfile.batch-gpu, Dockerfile.service.
  • README.md: Comprehensive deployment and architecture guide.

Key Design Decisions

Scale to Zero

The default configuration sets MinCapacity to 0 for ECS workers to minimize costs. Environment must be "woken up" via a utility Lambda or manual scaling.

Production Isolation

The S3 bucket production/ folder is read-only for users and only writable by automated execution roles (Lambda, Batch, ECS).

Centralized Secrets

All sensitive configuration (passwords, OAuth secrets) is stored in AWS Secrets Manager and injected into containers at runtime as environment variables.

Behavioral Guardrails (No-Go Zones)

  • No Hardcoded Secrets: NEVER hardcode passwords or keys in YAML templates or Dockerfiles. Use Secrets Manager parameters.
  • No Public S3: S3 buckets must never be public. Access is controlled via IAM and Cognito.
  • NAT Gateway: NAT Gateway is disabled by default to save costs. Enable it only when internet access is required for private subnets.
